# URL health checker

Полноценное приложение для асинхронной проверки списка URL. Сервер выполняет HTTP `HEAD`-запросы, максимум пять одновременно в рамках каждого задания, и сохраняет всё только в памяти процесса.

## Стек

- Backend: Node.js, Express, TypeScript
- Frontend: React, TypeScript, Zustand, Vite
- Контейнеризация: Docker и Docker Compose

## Быстрый запуск через Docker

Нужен установленный Docker Desktop. В корне репозитория выполните:

```bash
docker compose up --build
```

Откройте [http://localhost:8080](http://localhost:8080). API доступен на `http://localhost:3000`.

Остановка: `docker compose down`.

## Запуск без Docker

Нужен Node.js 22 или новее.

```bash
npm install
npm run dev
```

Откройте `http://localhost:5173`. Vite автоматически перенаправляет вызовы `/api` на backend, работающий на порту 3000.

Для production-сборки:

```bash
npm run build
npm run start
```

## API

### `POST /api/jobs`

Создаёт задание и сразу возвращает идентификатор.

```json
{ "urls": ["https://example.com", "https://httpbin.org/status/404"] }
```

Ответ: `201 { "jobId": "uuid" }`.

### `GET /api/jobs`

Возвращает краткие сведения обо всех заданиях: статус, дату, число URL и статистику.

### `GET /api/jobs/:id`

Возвращает подробности задания и результат для каждого URL: состояние, HTTP-код, ошибку и время обработки.

### `DELETE /api/jobs/:id`

Отменяет задание. Не начатые адреса получают состояние `cancelled`; уже начатые запросы могут завершиться, но задание остаётся отменённым.

## Особенности реализации

- Валидируются URL и размер списка (от 1 до 500).
- Параллельно обрабатывается до пяти URL на одно задание; разные задания независимы.
- После HEAD-запроса создаётся случайная задержка 0–10 секунд, и только затем фиксируется результат.
- Клиент опрашивает только выбранное незавершённое задание раз в 2 секунды. При переключении прежний интервал очищается, а поздний ответ не может перезаписать новое выбранное задание.
- Хранилище in-memory намеренно: после перезапуска API задания исчезают.
