# URL health checker

Fullstack-приложение для асинхронной проверки списка URL.

Сервис создаёт задания на проверку адресов, выполняет HTTP `HEAD`-запросы в фоновом режиме, показывает прогресс и результаты, а также позволяет отменить задание.

## Стек

- Backend: Node.js, Express, TypeScript
- Frontend: React, TypeScript, Zustand, Vite
- Контейнеризация: Docker, Docker Compose
- Хранение данных: in-memory

## Возможности

- Создание задания с одним или несколькими URL.
- Асинхронная обработка URL через HTTP `HEAD`-запросы.
- Не более пяти одновременных запросов в рамках одного задания.
- Одновременная обработка нескольких заданий.
- Случайная задержка от 0 до 10 секунд перед сохранением результата.
- Список всех созданных заданий со статистикой.
- Просмотр деталей каждого URL: статус, HTTP-код, ошибка, время обработки.
- Отмена задания: не начатые URL получают статус `cancelled`.
- Автоматический опрос активного задания на клиенте.

## Получение проекта

```bash
git clone https://github.com/mora-of-crims/url-health-checker.git
cd url-health-checker
```

## Быстрый запуск через Docker

Требуется установленный Docker Desktop.

```bash
docker compose up --build
```

После запуска откройте:

- Frontend: [http://localhost:8080](http://localhost:8080)
- API: [http://localhost:3000](http://localhost:3000)

Для остановки контейнеров:

```bash
docker compose down
```

## Запуск без Docker

Требуется Node.js версии 22 или новее.

Установите зависимости:

```bash
npm install
```

Запустите frontend и backend в режиме разработки:

```bash
npm run dev
```

Откройте в браузере:

```text
http://localhost:5173
```

Vite автоматически проксирует запросы `/api` на backend, который работает по адресу `http://localhost:3000`.

> Если Windows PowerShell блокирует команду `npm`, используйте `npm.cmd` вместо `npm`, например: `npm.cmd run dev`.

## Проверка работы

В поле создания задания вставьте URL по одному на строку:

```text
https://example.com
https://httpbin.org/status/200
https://httpbin.org/status/404
```

Нажмите «Запустить проверку».

В интерфейсе появятся:

- статус задания;
- прогресс обработки;
- статус каждого URL;
- HTTP-код либо текст ошибки;
- длительность проверки.

Для проверки отмены создайте задание с несколькими URL и нажмите «Отменить задание» до завершения обработки.

## API

### Создать задание

`POST /api/jobs`

Пример тела запроса:

```json
{
  "urls": [
    "https://example.com",
    "https://httpbin.org/status/404"
  ]
}
```

Пример ответа `201 Created`:

```json
{
  "jobId": "uuid"
}
```

### Получить список заданий

`GET /api/jobs`

Возвращает краткую информацию о заданиях:

- идентификатор;
- дату создания;
- статус;
- количество URL;
- количество успешных и ошибочных проверок.

### Получить детали задания

`GET /api/jobs/:id`

Возвращает сведения о задании и каждом URL:

- URL;
- статус;
- HTTP-статус;
- сообщение об ошибке;
- время начала и окончания;
- длительность проверки.

### Отменить задание

`DELETE /api/jobs/:id`

Помечает задание как `cancelled` и отменяет URL, обработка которых ещё не началась.

## Статусы

### Статусы задания

- `pending`
- `in_progress`
- `completed`
- `cancelled`
- `failed`

### Статусы URL

- `pending`
- `in_progress`
- `success`
- `error`
- `cancelled`

## Особенности реализации

- Принимаются только корректные `http` и `https` URL.
- Размер задания ограничен: от 1 до 500 URL.
- В рамках одного задания одновременно выполняется максимум 5 HEAD-запросов.
- Результат проверки сохраняется после искусственной случайной задержки 0–10 секунд.
- При переключении активного задания предыдущий polling корректно прекращается.
- Поздний ответ от старого задания не может перезаписать интерфейс нового задания.
- Данные хранятся в памяти процесса, поэтому после перезапуска backend все задания удаляются.
